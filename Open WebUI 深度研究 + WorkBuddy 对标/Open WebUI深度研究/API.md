## 函数
在 Open WebUI 中，**函数（Functions）** 的核心作用是让你可以使用 Python 代码**无缝插手“用户提问 ➔ 大模型推理 ➔ 结果输出”的整个生命周期**。

简单来说，如果把大模型比作“大脑”，那么 Functions 就是给这个大脑加上**安全门禁、滤镜、自动工作流和自定义插件**。

具体来说，函数可以用来实现以下几类核心应用场景：

### 1. 消息过滤与内容安全控制（Filter - Inlet/Outlet）

在消息发送给模型前（Inlet）或返回给用户前（Outlet）进行拦截与修改：

- **敏感词/脱敏过滤**：自动识别用户输入中的身份证号、手机号、API Key 等敏感信息并进行掩码替换（如 `138****1234`），防止数据泄露给外部大模型。
    
- **Prompt 动态注入/强化**：在用户提问前，根据当前时间、用户角色或系统状态，自动给 Prompt 加上前缀或系统提示词（如：“_请注意：当前用户是付费会员，请优先详细解答..._”）。
    
- **格式清洗与版权声明**：在模型回答完毕后，自动统一 Markdown 格式，或者在所有回答末尾自动挂载公司版权信息/免责声明。
    

### 2. 构建“自定义模型”与智能体工作流（Pipe）

通过写 Python 代码包装出一个全新的“虚拟模型”，直接显示在 UI 的模型下拉列表中：

- **多模型融合与路由（Router Agent）**：编写逻辑，让简单问题自动发给较便宜的 `DeepSeek-V3`，复杂逻辑推理问题自动转发给 `DeepSeek-R1` 或 `Gemini`。
    
- **对接非标准/私有 API**：如果你的企业内部有自定义的 AI 服务或特殊的 API，只需写一个 Pipe 函数，就能将其伪装成标准 Open WebUI 模型供团队使用。
    
- **复杂 Agent 工作流**：结合 LangChain、LlamaIndex 或自定义逻辑，实现包含“搜索 ➔ 思考 ➔ 调用数据库 ➔ 总结回答”的完整 Multi-Step 智能体。
    

### 3. UI 交互与快捷操作按钮（Action）

在聊天界面的每条回答下方添加自定义的功能按钮：

- **一键辅助工具**：例如在回答下方加一个“生成思维导图”、“一键翻译为英文”、“转换为 Markdown 表格”或“朗读文本”按钮，点击即对当前回答执行特定 Python 脚本。
    
- **数据导出与对接**：点击按钮直接将当前对话生成 PDF 发送到邮箱，或者把总结好的内容自动同步到 Notion / 钉钉 / 飞书维基。
    

### 4. 系统集成与权限/额度管理

- **用户用量审计与日志**：在函数里记录每个用户提问的 Token 消耗、调用频次，并将日志上报到公司内部的监控系统。
    
- **动态控制面板（Valves）**：通过定义 `Valves`，管理员或普通用户可以在 UI 界面上直接拉动滑块或修改输入框（如设置 API 密钥、选择翻译语言、调节开关），无需修改底层 Python 代码即可改变逻辑行为。







- 在 Open WebUI 中，**管道模型（Pipe）** 和 **模板模型（Model / Template）** 都是创建自定义模型的方式，但它们的**底层逻辑、灵活度和实现难度**有本质区别：

  

### 1. 核心区别一览

|**维度**|**管道模型（Pipe）**|**模板模型（Model / Template）**|
|---|---|---|
|**底层驱动**|**纯 Python 代码**（通过 Function 创建）|**提示词（Prompt）与系统参数**|
|**灵活性**|**极高**（可调用外部 API、做复杂条件判断、执行多步工作流）|**中等**（仅限于预设系统提示词、温度值等参数）|
|**上手难度**|需要具备基础的 Python 编程能力|非常简单，无需写代码，在 UI 界面点击即可创建|
|**执行机制**|彻底**接管/替代**原始模型的请求与响应逻辑|作为**外壳（Wrapper）**，本质还是把包装好的 Prompt 发给底层的基础大模型|
|**典型应用**|智能路由、多 Agent 协作、接私有 API、自动化数据处理|角色扮演（如“专业翻译官”）、特定任务助手（如“Code Review 专家”）|

### 2. 详细解析

#### 管道模型（Pipe）

- **原理**：利用 Open WebUI 的 Function 机制编写 `type: pipe` 的 Python 类。
    
      
    
- **特点**：它本质上是一个**独立的动态程序**。它接收用户的输入，但接下来干什么完全由你的 Python 代码说了算——你可以让它去爬取网页、查 SQL 数据库、跑 Python 代码，或者根据用户问题的难易程度自动路由给不同的 API（例如简单的给 `DeepSeek-V3`，复杂的给 `DeepSeek-R1`）。
    
      
    
- **类比**：就像给系统装了一个**自动化的机器工作流水线**。
    
      
    

#### 模板模型（Model / Template）

- **原理**：在 Open WebUI 的 **Workspace -> Models** 里，基于某一个现有大模型（如 `DeepSeek-R1`），预设好 **System Prompt（系统提示词）**、`Temperature`（随机度）以及默认关联的知识库/工具。
    
      
    
- **特点**：它本质上是**静态的配置预设**。它并没有改变大模型的运作机制，只是帮用户省去了每次手动输入“_你是一个 Python 专家，请用严谨的语气回答..._”的麻烦。
    
      
    
- **类比**：就像给大模型戴上了一顶**预定义好的角色面具（例如预设的人设卡片）**。
    
      
    

### 3. 如何选择？

- **选模板模型（Template）**：如果你只是想创建一个固定人设或特定用途的助手（如“英语润色专家”、“简历修改器”），用界面上的预设模板即可，最快几秒钟就能建好。
    
      
    
- **选管道模型（Pipe）**：如果你需要涉及**复杂的逻辑处理、多模型切换、对接外部系统或写代码控制交互**，则必须使用 Pipe。
