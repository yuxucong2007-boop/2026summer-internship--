# 逐功能研究

## 聊天对话

**功能是什么：**用户输入问题、选择模型并持续追问的主流程。它承载文本、附件、工具、建议提示和多轮上下文。
![[Pasted image 20260804153857.png]]
**怎么用：**

1. 在首页输入框输入问题。
2. 确认输入框右侧当前模型。
3. 需要文件或工具时先从输入区左侧入口添加。
4. 提交后在同一会话中追问或编辑、重新生成。

**亮点：**

- 首屏直接进入对话，低认知负担。
- 当前模型常驻输入区附近，用户知道是谁在回答。
- 普通聊天能继续衔接文档、搜索、语音和记忆。

**不足：**

- 输入区入口密度高，新用户需要识别图标。
- 模型能力和实例工具开关的边界不够显性。
- 回答质量仍受后端模型、连接和上下文限制影响。



## 模型管理

**功能是什么：**负责接入和治理可用模型，包括模型来源、模型 ID、标签、连接地址、凭证和卸载等能力。
![[Pasted image 20260804155306.png]]
**怎么用：**

1. 管理员接入本地或 OpenAI 兼容模型服务。
2. 配置服务地址、访问凭证和模型 ID。
3. 刷新模型列表并确认模型可用。
4. 用户在聊天输入区选择模型。

**亮点：**

- 兼容 OpenAI 风格接口。
- 前端资源显示可聚合多个模型来源，并支持前缀避免重名。
- 管理配置与聊天选择分离。

**不足：**

- 配置复杂度取决于外部服务、凭证和协议兼容。
- 模型名称、ID、前缀和来源可能混淆。
- 缺少统一的速度、价格、上下文和工具能力对比。


## 多模型切换

**功能是什么：**在同一会话或任务中更换当前模型，用不同模型继续回答、重新生成或对比结果。
![[Pasted image 20260804155352.png]]
**怎么用：**

1. 打开输入框旁的模型选择器。
2. 选择另一个已接入且有权限的模型。
3. 用新模型继续下一轮，或对同一问题重新生成。
4. 记录模型名称、上下文和回答差异。

**亮点：**

- 切换入口靠近输入区，操作成本低。
- 适合快模型草稿、强模型复核、本地模型处理隐私数据。
- 在同一会话中保留上下文，便于复核。

**不足：**

- 切换不等于公平比较，上下文和工具状态会干扰结论。
- 不同模型可能不兼容同一工具、图片或上下文长度。
- 若不显示成本和延迟，用户难以选择。


## 流式输出

**功能是什么：**模型生成片段到达后立即渲染，用户无需等待完整答案完成。当前实例开启 WebSocket，前端存在停止任务接口。

**怎么用：**

1. 提交问题。
2. 观察回答逐步出现。
3. 方向错误或内容足够时点击停止。
4. 完成后复制、追问或重新生成。

**亮点：**

- 即时反馈，减少等待焦虑。
- 可中途止损，节省时间和 token。
- 生成、停止和错误可形成明确状态。

**不足：**

- 首 token 延迟仍然存在。
- 网络抖动可能造成断线、重复片段或 Markdown 半成品。
- 停止后的半截回答状态需要清晰语义。

## 对话历史管理

**功能是什么：**保存、定位、组织和清理聊天会话，包括历史列表、搜索、标题、标签、归档、删除和隐私控制。
![[Pasted image 20260804155544.png|406]]
**怎么用：**

1. 从左侧历史列表打开已有会话。
2. 用搜索定位旧对话。
3. 重要会话手动重命名或归档。
4. 不再需要或敏感会话执行清理。

**亮点：**

- 回访路径短，历史就在聊天左侧。
- 自动标题和标签可降低维护成本。
- 列表浏览与搜索定位分工明确。

**不足：**

- 自动标题可能含糊。
- 历史越多，侧栏越容易变成噪声。
- 删除、归档、临时聊天和服务端留存的隐私语义必须清楚。
