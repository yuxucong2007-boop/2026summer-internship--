## 一、目标用户群体

本产品面向三类用户，定位不同、诉求各异：

### 用户群 A：公司内部运营/运维人员

- **身份**：公司内部员工，负责系统运维、监控、知识积累与流程管理
- **核心诉求**：
  1. **快速获取答案**：减少翻文档、跑系统的时间，遇到问题能即时得到指引
  2. **知识沉淀**：将散落在个人、群聊、文档中的运维经验结构化积累，防止经验随人员流失
  3. **流程标准化**：将高频操作、故障处理流程固化为标准 SOP，新人可直接复用，减少重复踩坑
  4. **统一管理**：形成可检索、可维护的知识体系，便于后续审计、迭代和团队对齐
- **典型场景**：查运维手册、看监控告警、做故障分析、沉淀故障复盘、生成标准操作文档
- **关键词**：效率、知识沉淀、标准化、可复用

### 用户群 B：业务部门内部员工

- **身份**：采购、电商、行政、财务、数据分析等职能人员
- **核心诉求**：
  1. **流程自动化**：把日常重复操作（审批、报价、登记）自动化，减少在多系统间手动切换
  2. **数据查询与分析（问数）**：用自然语言直接查数仓，不依赖数据分析师取数，能自助获取业务指标
  3. **内容生成**：快速输出报告、比价表、邮件等工作文档，减少人工整理时间
  4. **多系统协同**：出差申请、供应商询价、订单登记等跨系统操作通过 AI 一次完成，不再在钉钉/OA/采购系统间来回跳
- **典型场景**：出差申请自动提审、供应商询价汇总比价、数仓自助问数、订单登记、生成业务报告
- **关键词**：流程自动化、自助问数、多系统打通、内容生成

### 用户群 C：业务部门服务的 B 端外部客户

- **身份**：业务部门将 AI 能力打包后交付的下游企业客户
- **核心诉求**：
  1. **通用 AI 能力开箱即用**：对话助手、知识问答、内容生成等市面上主流 AI 能力，打包交付后直接可用，无需客户自建
  2. **场景适配**：在通用能力基础上做有限的场景配置（如定制知识库内容、配置特定工作流），满足客户自身业务习惯
  3. **私有化部署（少数客户）**：数据安全要求高的客户（政企、金融等）需要在自己环境内部署，数据不出内网
- **典型场景**：客户使用预置好的 AI 工作台处理日常事务；对数据敏感的客户申请私有化部署版本
- **关键词**：通用能力交付、低配置成本、按需私有化
- **备注**：大多数客户需要的是"拿来即用的标准化 AI 工具包"，私有化定制是少数高价值客户的附加服务，不是主流交付模式

## 二、产品定位与商业化范围

### 产品定位一句话

> **企业 AI 工作助手平台**：以对话为入口，帮助运维人员沉淀知识与标准化流程，帮助业务人员自助取数与自动化操作，同时作为可打包交付的 AI 能力底座服务外部客户。

定位是**能力平台**，不替代任何现有系统，而是在所有系统之上提供统一的 AI 操作界面。

### 产品边界

- **做什么**：第三章列出的 8 项核心能力
- **不做什么（轻量接入替代）**：OA 审批引擎本身、差旅管理系统、数据仓库与 BI 工具、IM 通信工具（企微/钉钉）

### 可商业化的客户群

三类用户群对应三条商业化路径：

| 对应用户群                       | 客户类型                                               | 付费动机                                     | 推荐收费模式                                     |
| -------------------------------- | ------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------ |
| **用户群 A**（内部验证）   | 公司内部先行使用                                       | 验证产品能力，积累案例                       | 内部成本分摊，不对外收费                         |
| **用户群 B**（主力商业化） | 有数仓问数需求的中型企业；需要流程自动化的职能团队     | 自助取数降低分析师依赖；减少重复操作成本     | SaaS 订阅（按人/月）+ Token 用量叠加             |
| **用户群 C**（规模化交付） | 业务部门下游客户（标准包）；数据敏感的大客户（私有化） | 开箱即用的 AI 能力包；数据不出内网的合规要求 | 标准包：白标/OEM 授权；私有化：项目制 + 年度维护 |

**商业化路径**：内部验证（A）→ 中型企业（B）→ 外部客户打包交付（C 标准包）→ 少数高价值客户私有化（C 定制）。

## 三、产品核心能力总览

产品共 **8 项核心能力**，按"基础层 → 场景层 → 支撑层"三层组织。每项标注主要服务的用户群，以及对三类用户的具体价值。

### 基础层：所有场景都要用的底座

| 核心能力                               | 主要服务  | 对三类用户的价值                                                                                                                                                                                                           |
| -------------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **自然语言对话界面**             | A / B / C | A：即时查询故障处理方法；B：发起审批、取数、触发工作流；C：开箱即用的 AI 交互入口                                                                                                                                          |
| **知识库（导入/检索/标签管理）** | A / B / C | A：查运维手册与历史故障；B：查采购规则、产品信息、业务标准；C：使用业务方预置的知识包                                                                                                                                      |
| **MCP 插件化通用适配层**         | A / B / C | A：触发监控查询与系统操作；B：跨系统自动化（审批/取数/订单登记一次完成）；C：对接客户已有系统。各类外部系统（钉钉OA/云枢/携程/九数云等）封装为标准 MCP 插件，不同客户/场景按需挂载，新增系统只需新增插件，不改平台核心代码 |

### 场景层：解决具体业务诉求的模块

| 核心能力                            | 主要服务       | 对三类用户的价值                                                                                               |
| ----------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------- |
| **知识沉淀与 SOP 管理**       | A 为主，B 次之 | A：经验结构化沉淀为标准流程，防止知识随人员流失；B：沉淀业务规范供团队参考；C：客户管理自己的知识资产          |
| **智能文档助手**              | A / B / C      | A：私有文档→SOP / 故障复盘 / 知识要点；B：报告 / 比价表 / PPT 骨架；C：数据不出网的本地文档生成（差异化卖点） |
| **数仓问数全链路**            | B 为主         | B：自助取数，不再依赖数据分析师；A / C：按需扩展使用                                                           |
| **工作流编排引擎 + 场景模板** | B 为主         | B：预置采购 / 行政 / 出差等场景模板；A：运维流程自动化；C：客户可配置自身工作流                                |

### 支撑层：商业化与运营基础

| 核心能力                    | 主要服务      | 价值说明                        |
| ----------------------- | --------- | --------------------------- |
| **Token 计量计费 + 用户权限体系** | A / B / C | 商业化度量基础，多租户管理，支撑三类用户群的隔离与计费 |

---

### 能力叠加逻辑

```
基础层：对话界面 + 知识库 + 外部连接层
              ↓
场景层：知识沉淀 / 文档助手 / 数仓问数 / 工作流
              ↓
支撑层：计量计费 + 权限体系
              ↓
垂直场景模板（在底座上配置，不重建底层）
```

**核心逻辑**：基础层能力复用率最高（三类用户全覆盖），场景层针对不同用户群的痛点独立建设，每个新场景只需在底座上增加工作流配置，不需重建底层。知识沉淀模块尤其关键——用户日常产生的内容（故障复盘、比价结果、审批记录）可持续回流知识库，形成资产积累的正向循环。

## 四、自建 vs 轻量接入：关键决策

**原则**：上节 8 项核心能力均需自建；其他平台已成熟、用户已有习惯的执行系统，只做连接层。

唯一需要单独说明的是**数仓问数**——它本可轻量接入，但业务方明确要求完整建设：

> 将数仓标准做成知识库 + 工作流问题清洗的轻量路径，复杂场景适配性弱，最终仍需调优，不能满足需求。

**数仓问数必须完整建设的子能力：**

| 层次       | 子能力                   | 说明                                                                                                    |
| ---------- | ------------------------ | ------------------------------------------------------------------------------------------------------- |
| 数据接入层 | 数据源接入与分层管理     | 支持 ODS/DWD/DWS/ADS 各层数据源配置接入，对接九数云已有数据体系                                         |
| 语义调优层 | 表路由（Schema Linking） | 根据用户问题自动判断使用哪张或哪几张表，表数 >5 或业务边界模糊时配置                                    |
| 语义调优层 | 指标口径管理             | 分三层：同义词（表达映射）/ 专业名词（统计范围/过滤条件/时间粒度）/ 业务逻辑（规则约束）                |
| 语义调优层 | NL2SQL 生成与调优        | 生成 SQL 并通过结果回译校验减少错误；高级工具：样例库（典型问法映射）/ SQL 模板（口径严格场景直接执行） |
| 语义调优层 | 问题预清洗工作流         | 问题标准化 → 参数提取 → 意图路由                                                                      |
| 安全控制层 | 行列级权限管理           | 控制不同用户可查询的数据集、数据行与字段范围                                                            |
| 展示控制层 | 输出模板与展示配置       | 图表/数据表/报告等多种输出样式；支持是否展示思考过程、数据洞察解读、无数据/无权限兜底回复               |

> 数仓问数是本产品技术难度最高的模块，核心挑战在于指标口径统一和多表 Join 推理，需业务方提供标准化数仓元数据配合建设。

**与业务方现有数仓（九数云）的关系**：业务方使用九数云作为数仓管理系统，客户数据通过取数工具层（API/RPA）流入九数云。我方问数能力定位为在九数云之上提供 AI 问数层，不替代九数云，而是：复用九数云已有的数据分层、指标口径、清洗入参等标准化体系，通过数据接入层对接九数云，在此基础上提供 NL2SQL、表路由、SQL 调优等 AI 化能力。

**轻量接入的外部系统（不重建，只做连接）：**

| 外部系统                 | 接入方式                        |
| ------------------------ | ------------------------------- |
| 钉钉/飞书 OA 审批流      | Webhook 推送审批单，监听回调    |
| 企微/微信群机器人        | Webhook 接收消息，AI 处理后回复 |
| 差旅系统（携程企业版等） | MCP/API 查询行程、预订结果      |
| 采购系统（云枢等）       | API 触发订单登记、工作流推送    |
| 钉钉知识文档             | 一次性抓取清洗后导入平台知识库  |
| PPT/脑图渲染             | 对接 Gamma 等工具的导出接口     |

## 五、分期推进建议

分期逻辑以**服务用户群的优先顺序**为驱动，而非单纯按技术难度排序。

### 一期：服务用户群 A，跑通知识底座

目标：让内部运维/运营人员能用起来，同时验证知识库和文档助手的核心能力。

| 功能                                 | 说明                                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------------------- |
| 对话界面 + 用户权限体系              | 基础入口和多租户管理                                                                  |
| 知识库（导入 + 混合检索 + 标签管理） | 运维手册、故障案例的检索查询                                                          |
| 知识沉淀与 SOP 管理                  | 故障复盘结构化沉淀，生成可复用标准流程                                                |
| 智能文档助手基础能力                 | 文档上传、问答、摘要、SOP 生成                                                        |
| MCP 插件化通用适配层                 | 各类外部系统封装为标准 MCP 插件，按需挂载；是工具箱场景绑定的底层扩展机制，需早期建好 |
| Token 计量计费                       | 商业化度量基础                                                                        |

### 二期：服务用户群 B，打通数据与流程

目标：覆盖业务部门的自助问数和流程自动化核心诉求。

| 功能                      | 说明                                               |
| ------------------------- | -------------------------------------------------- |
| 数仓问数全链路            | 数据源接入、表路由、NL2SQL、指标口径管理、输出模板 |
| 工作流编排引擎 + 场景模板 | 出差申请、采购询价、订单登记等预置场景             |
| MCP 通用适配层            | 打通 OA 审批、差旅系统、采购系统等外部连接         |
| 钉钉文档导入工具          | 将现有钉钉知识迁移进平台知识库                     |
| 企微机器人接入            | 扩展业务部门的消息触发入口                         |

### 三期：服务用户群 C，对外打包交付

目标：将一、二期验证过的能力标准化，形成可交付的产品包。

| 功能                     | 说明                                                                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 标准化产品包（白标/OEM） | 知识库 + 文档助手 + 对话界面打包，低配置成本交付                                                                                                    |
| 私有化/数据脱敏部署模式  | 两档方案：①云端模型+数据代号化（真实数据本地转代号后发云端模型，不暴露原始数据，主推，比完整私有化更现实）；②完整私有化部署（极少数高要求大客户） |
| 场景模板市场             | 沉淀可复用场景模板，降低新客户接入成本                                                                                                              |
| 知识图谱构建             | 提升复杂知识问答准确性（差异化能力）                                                                                                                |
