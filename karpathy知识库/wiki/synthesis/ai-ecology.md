# AI 生态技术栈全景——从 LLM 到应用的完整链路

> 综合 `AI基本知识.md` 的内容，梳理大模型生态中核心概念的分层关系与协同逻辑。

## 一句话全景

> 开发者通过 **Prompt Engineering** 指导 **Agent（智能体）** 运作；Agent 遇到专业知识时，利用 **Embedding** 技术去 **向量数据库** 中通过 **RAG** 检索资料；遇到需要执行的操作，通过 **MCP 协议** 调用外部工具；而如果基础模型在特定领域表现不够专业，还可以通过 **Fine-tuning** 对其进行深度改造。**整个工作流程由 Harness Engineering 管理、测试和保障。**

## 四层架构

```
┌─────────────────────────────────────────────────┐
│            Harness Engineering                   │
│    （安全管控 · 状态管理 · 执行沙箱 · 回退）       │
├─────────────────────────────────────────────────┤
│                   AI Agent                       │
│    （感知 → 规划 → 执行 → 反思）                  │
├──────────────┬──────────────────┬───────────────┤
│     RAG      │       MCP       │   Prompt       │
│  (知识检索)   │    (工具调用)    │  (指令控制)    │
├───────┬──────┴──────┬───────────┴───────┬───────┤
│Embed  │  Vector DB  │  Fine-tuning      │  LLM  │
│(向量化)│  (向量存储)  │  (模型定制)       │ (引擎)│
└───────┴─────────────┴───────────────────┴───────┘
```

## 关键洞察

### 1. RAG vs Fine-tuning：何时用哪个？

| 维度 | RAG | Fine-tuning |
|------|-----|-------------|
| 是否改变模型 | 否 | 是（改权重）|
| 更新知识 | 即时（换文档即可） | 慢（需重新训练）|
| 适合场景 | 事实查询、企业知识库 | 格式控制、风格固定、专业能力 |
| 成本 | 低 | 高 |
| **建议** | **能 RAG 就先 RAG，不够再微调** |

### 2. RAG vs MCP：两种扩展的分工

这两个概念最容易混淆。关键区别：
- **RAG** 是"读"——从外部获取**知识**（文档、数据库记录），扩充 LLM 的上下文
- **MCP** 是"写"——执行**操作**（发消息、更新数据库、运行代码），扩展 LLM 的行动能力

### 3. AI 幻觉的双面性

虽然工程上 RAG 是用来抑制幻觉的，但在创意领域（写作、头脑风暴、游戏设计），"幻觉"本质上就是**想象力**。看场景决定是抑制还是利用。

## 引申思考

1. 当前这 10 个概念中，哪些会随着技术发展而消失？哪些是永久的？
   - MCP 可能会被更好的标准取代
   - Prompt Engineering 可能随着模型理解能力的提升而变得不重要
   - **LLM、Agent、RAG** 这三个概念很可能长期存在

2. 对于知识库构建者来说，RAG 和 LLM Wiki（[[karpathy的wiki方法论]]）是两种不同的范式：
   - RAG：运行时检索，不维护持久结构
   - LLM Wiki：构建时编译，维护持久结构
   - 两者可以互补——Wiki 作为"半结构化知识层"，RAG 作为"实时检索层"
