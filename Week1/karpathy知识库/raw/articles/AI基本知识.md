
### 1. 大型语言模型（LLM）

- **什么是LLM：**它是现代人工智能的“大脑”或基础。LLM是一个庞大的深度学习模型，它基于海量文本数据进行训练，用于预测序列中的下一个单词。
    
- **核心功能：**理解和生成自然语言，解决复杂的推理任务，编写代码，以及处理非结构化文本。

### 2. Prompt 提示词

- **它是什么：**您提供给 LLM 的输入文本、指令或查询，以指导其输出。
    
- **核心功能：**由于LLM是通用的，提示信息就像方向盘一样，它为模型设定了上下文、指令、输出格式、角色（例如， _“扮演高级软件工程师” ）和约束条件。_
    
- **提示工程：**构建提示（使用诸如少样本提示或思维链等技术）以可靠地获得高质量回复的学科。
    

### 3. AI Agent（智能体）

- **它是什么：**一个由 LLM 驱动的自主系统，可以**规划、使用工具并采取行动**来实现具体的、多步骤的目标，而不仅仅是回答单个文本提示。
    
- **核心功能：**标准的语言学习管理器 (LLM) 只是回复文本，而人工智能代理则以循环方式运行：
    
    1. **感知：**读取用户输入和当前状态。
        
    2. **计划：**将目标分解为可执行的步骤。
        
    3. **执行：**使用外部工具（浏览网页、运行代码、调用 API）。
        
    4. **反思：**评估结果，并在必要时调整策略。
        
- **例如：**一名代理的任务是_“为我的商务旅行预订机票和酒店，预算不超过 1000 美元”，_他将搜索航班 API，验证酒店价格，比较行程，并汇总或完成预订。
    

### 4. RAG（检索增强生成）

- **它是什么：**一种将LLM的响应建立在特定、外部或私有数据集（如公司文件、代码库或个人文件）之上的技术。
    
- **核心功能：** LLM（法学硕士）可能面临两大问题：虚构（捏造事实）和知识过时。RAG（红绿灯）通过以下方式解决这些问题：
    
    1. **检索：**在数据库（通常是 Vector DB）中搜索与用户查询相关的事实。
        
    2. **增强功能：**将检索到的文档作为上下文附加到 LLM 的提示中。
        
    3. **生成：指示 LLM**_严格_根据检索到的上下文编写响应。
        
- **主要优势：**防止出现幻觉，并可在不重新训练基础模型的情况下实时访问专有企业数据。
    

### 5.harness工程 线束工程（代理线束）

- **它是什么：**围绕 LLM 或 AI 代理构建的周边基础设施、控制框架和执行环境，以保持其可靠性、安全性和高效性。
    
- **核心功能：**生产中的原始LLM可能难以预测。安全带起到“安全笼和转向装置”的作用，用于操控：
    
    - **内存管理：**存储短期和长期对话历史记录。
        
    - **防护措施和过滤：**检查输入和输出是否存在安全风险或有害内容。
        
    - **执行沙箱：**在隔离、安全的环境中运行代理生成的代码或命令。
        
    - **评估与回退：**检测代理何时陷入无限循环或某个步骤失败，然后重新路由或通知人工。
        

### 6. MCP协议（模型上下文协议）

- **它是什么：**一个开放标准，旨在统一人工智能应用程序如何连接到外部工具、数据库和本地文件系统。
    
- **核心功能：**在 MCP 出现之前，每个 AI 工具或代理框架都必须为每个外部服务编写自定义集成代码（例如，GitHub 的自定义插件、Google Drive 的自定义插件、Postgres 的自定义插件）。MCP 将此标准化为客户端-服务器模型：
    
    - **MCP 客户端：** AI 应用程序（如 Claude Desktop 或 IDE 扩展）。
        
    - **MCP 服务器：**轻量级插件，用于公开工具/数据（例如本地 SQLite 数据库、Slack 集成或系统终端）。
        
- **主要优势：**可以将 MCP 理解为“人工智能应用的 USB-C”。它允许任何人工智能代理立即连接到任何 MCP 支持的数据源或工具，而无需为每个提供商进行自定义集成。
    

### 它们如何协同工作

```
                             │
                             ▼
  User Input ──► [ Prompt ] ──► [ AI Agent ] ──► [ LLM (Reasoning Engine) ]
                                   │
                     ┌─────────────┴─────────────┐
                     ▼                           ▼
            [ RAG Retrieval ]            [ MCP Protocol ]
         (Fetches Private Data)     (Executes External Tools/APIs)
```

1. 您向**人工智能代理提供****提示**。
    
2. 该智能体的核心推理由**LLM**提供动力。
    
3. 为了收集事实，该代理使用**RAG**来提取内部知识。
    
4. 要执行操作（例如，更新数据库或向 Slack 发送消息），代理通过**MCP 协议**进行连接。
    
5. **整个工作流程由Harness Engineering**进行管理、测试和保障。
这里把大模型生态中最核心的这 **7 个关键概念** 按照从“基础输入”到“应用架构”的逻辑，为你一次性梳理清楚：

### 1. Prompt Engineering（提示词工程）

- **是什么**：给大模型写指令的“说话艺术”与“技术规范”。
    
- **做什么**：大模型就像一个通晓万物的专家，但你需要用准确的语言引导它。提示词工程包含角色设定（如“你是一名资深架构师”）、少样本提示（Few-Shot）、思维链（Chain-of-Thought）等技巧，用来精确控制模型的输出质量和格式。
    

### 2. Embedding（向量嵌入）

- **是什么**：将人类的文本、图片、音频等高维数据，转换成计算机能理解的一串高维高精度的**数字数组（向量）**。
    
- **做什么**：人类看文字看含义，计算机看文字只看代码。Embedding 的核心 magic 在于“语义近的，向量距离也近”。例如，“猫”和“狗”转换成向量后在多维空间里的距离，远比“猫”和“微波炉”近得多。
    

### 3. 向量数据库（Vector Database）

- **是什么**：专门用来存储和高效检索 Embedding（向量）数据的特殊数据库（如 Milvus, Pinecone, Chroma 等）。
    
- **做什么**：传统数据库（如 MySQL）擅长查“完全匹配的字符串”，而向量数据库擅长做“语义相似度搜索”（KNN/ANN 检索）。当你有数百万份文档需要让 AI 快速查找最相关的内容时，必须依赖向量数据库。

### 6. Fine-tuning（微调）

- **是什么**：**“二次进修”**。在已有的通用大模型（如 Llama 3、GPT-4）基础上，使用特定的业务数据集再次进行训练，改变模型的内部权重。
    
- **做什么**：让模型掌握特定的专业领域知识、固定独特的输出风格/格式，或者大幅提升在特定任务（如医学诊断、法律文书生成）上的执行表现。

### 一句话总结它们的关系

> 开发者通过 **Prompt Engineering** 指导 **Agent（智能体）** 运作；Agent 遇到专业知识时，利用 **Embedding** 技术去 **向量数据库** 中通过 **RAG** 检索资料；遇到需要执行的操作，通过 **MCP 协议** 调用外部工具；而如果基础模型在特定领域表现不够专业，还可以通过 **Fine-tuning** 对其进行深度改造。


## ****AI为什么会产生幻觉

AI 产生“幻觉”（Hallucination，即煞有介事地编造错误事实或虚构信息）并不是偶然的 Bug，而是由**大语言模型（LLM）的底层技术架构和训练方式**决定的。

从技术原理到应用层面，主要有以下几个核心原因：

### 1. 底层机制：它是“概率预测机”，而不是“知识数据库”

- **本质是预测下一个词：** 大模型并不是像搜索引擎那样去翻阅具体的知识库，而是根据统计概率，计算“在前面这些词后面，最可能接哪个词”。
    
- **追求“流畅度”而非“绝对真理”：** 模型训练的目标是让生成的内容在语法和逻辑流畅度上符合人类表达习惯。当遇到不确定的知识时，为了保证语句的连通性，它会优先选择“听起来合理”的词汇填补空缺，从而织造出看起来非常专业的假话。
    

### 2. 数据源头：训练数据的噪音与局限

- **训练数据存在错误或冲突：** 训练 LLM 使用了互联网上的海量文本，其中本身就充斥着虚假信息、偏见、网民的调侃、未经证实的传言甚至矛盾的说法。
    
- **数据时效性与覆盖盲区：** 如果某个领域（如极其冷门的学术知识、某个小众接口的文档）在训练数据中出现频率极低，或者问题涉及模型训练截止时间之后的新知识，模型在缺乏足够上下文时就会“强行填空”。
    

### 3. 训练过程的副作用（RLHF 与过度迎合）

在通过“基于人类反馈的强化学习（RLHF）”对模型进行微调时，可能带来两个副作用：

- **过度讨好（Sycophancy）：** 模型被引导去生成人类“喜欢看”的回答。如果你在提问时带有诱导性（例如：“为什么周杰伦在2015年获得了诺贝尔文学奖？”），模型为了顺应你的前提，可能会顺着这个错误前提继续编造细节。
    
- **盲目自信：** 人类标注员在给模型评分时，往往倾向于给“表达自信、结构完整”的回答打高分，这导致模型学会了用非常笃定的语气去说假话。
    

### 4. 压缩损失：高维信息的“模糊记忆”

大模型将数 TB 的文本知识“压缩”进了几百亿或几千亿个浮点数参数（权重）中。这种压缩是**有损的**，类似于人类的记忆——模型记住了概念之间的关联和模式，但很难像数据库那样做到对精确数据（如电话号码、具体日期、复杂计算结果）的无损提取。
